# 模型接入指南 —— API 调用 vs 本地部署

> 依据：[MiniMax 官方文档](https://platform.minimax.io/docs/api-reference/api-overview)
> 适用：本项目（floze_clone）的模型后端配置

---

## ⚠️ 选型结论（2026-09-21 实测修订）

**主力模型：`MiniMax-M3` + `thinking: {type: "disabled"}`**

早期计划用 M2.7 做主力，实测后被推翻 —— **M2.7 的 thinking 无法关闭**：

```
M2.7  max_tokens=300   → think 1215 字符，正文 0     ❌
M2.7  max_tokens=1000  → think 4781 字符，正文 0     ❌
M2.7  thinking:{disabled} → 参数无效                 ❌

M3    thinking:{disabled} → 300 token 出 1440 字符   ✅
```

M3 不仅可控，成本还低 4 倍以上。详见 `floze_reverse/模型替换实测评估.md` §11。

切换方式（环境变量，无需改代码）：

```bash
# 默认就是 M3，一般不用设
export MINIMAX_MAIN_MODEL="MiniMax-M3"
```

## ⚠️ 商业授权提醒

官方部署文档里有这段原话，对商业产品极其关键：

> The MiniMax-M2.7 License permits the **personal, research, and educational** uses
> listed in the license. **Commercial use includes attribution and prior-authorization
> requirements.**

- 权重是**开源**的，可以下载自部署
- 但**商业使用需要署名 + 事先授权**
- 与直接调 API（标准商业服务条款）不同

**结论**：产品要商用的，走官方 API 更省心；若要本地部署商用，先走授权流程。

---

## 两条路径对比

| 维度 | 官方 API | 本地部署（SGLang） |
|---|---|---|
| 接入成本 | 几分钟 | 需 4×A100/H100 级别硬件 |
| 单位成本 | 按量付费 | 电费 + 折旧（量大才划算） |
| 数据出境 | 需评估 | **数据不出内网** |
| 内容可控性 | 受平台审核约束 | 完全自主 |
| 商用授权 | 标准服务条款 | **需事先授权 + 署名** |
| 运维负担 | 无 | 自己维护推理集群 |

**建议**：先用 API 验证产品，等单日调用量稳定后再评估是否自部署。

## 路径 A：官方 API（推荐起步）

```bash
cd floze_clone
# 新 key 用环境变量注入，不要落盘
export MINIMAX_API_KEY="你的key"
python3 server.py
```

模型自动解析为 `MiniMax-M3`（全部档位，均关闭 thinking）。

## 路径 B：本地部署

### B1. 起推理服务（官方参考配置）

```bash
docker run --gpus all \
  --shm-size 32g \
  -p 30000:30000 \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  --ipc=host \
  lmsysorg/sglang:v0.5.10.post1 \
  sglang serve \
  --model-path MiniMaxAI/MiniMax-M2.7 \
  --tp 4 \
  --tool-call-parser minimax-m2 \
  --reasoning-parser minimax-append-think \
  --trust-remote-code \
  --mem-fraction-static 0.85 \
  --host 0.0.0.0 \
  --port 30000
```

**参考硬件**（官方文档）：

| 平台 | 硬件 | 镜像 |
|---|---|---|
| NVIDIA | A100 / H100 / H200 / B200 | `lmsysorg/sglang:v0.5.10.post1` |
| NVIDIA | B300 / GB300 | `...:v0.5.10.post1-cu130` |
| AMD | MI300X / MI325X | `...:post1-rocm720-mi30x` |
| AMD | MI355X | `...:post1-rocm720-mi35x` |

常见拓扑：**4 卡 TP4** 或 **8 卡 TP8 + EP8**。

> 官方警告：并行度、KV cache 容量、可用上下文长度三者互相依赖，
> **不要只改 GPU 数量**，硬件变化时请用 SGLang configurator 生成完整配置。

### B2. 验证服务

```bash
curl http://localhost:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"MiniMaxAI/MiniMax-M2.7",
       "messages":[{"role":"user","content":"hello"}],
       "max_tokens":64}'
```

### B3. 让本项目接上本地端点

**只需两个环境变量，无需改任何代码**：

```bash
export MINIMAX_BASE_URL="http://localhost:30000/v1"
export MINIMAX_MODEL_PREFIX="MiniMaxAI/"     # 本地权重带组织前缀
python3 server.py
```

如果本地**只部署了 M2.7**（没部署 M3），再补一个：

```bash
export MINIMAX_EPIC_MODEL="MiniMax-M2.7"     # epic 档也用 M2.7
```

## 代码如何实现切换（`llm.py`）

```python
API_BASE     = os.environ.get("MINIMAX_BASE_URL", "https://api.minimax.io/v1")
MODEL_PREFIX = os.environ.get("MINIMAX_MODEL_PREFIX", "")
EPIC_MODEL   = os.environ.get("MINIMAX_EPIC_MODEL", "MiniMax-M3")

def resolve_model(logical_name):
    return f"{MODEL_PREFIX}{logical_name}" if MODEL_PREFIX else logical_name

def api_key():
    k = os.environ.get("MINIMAX_API_KEY", "").strip()
    if not k and is_local_deploy():
        return "EMPTY"        # SGLang 不需要真实 key
    return k
```

**设计要点**：档位配置里存的是**逻辑模型名**（`MiniMax-M2.7`），
请求时才加前缀。所以官方 API 与本地部署共用同一套业务代码。

### 实测验证

```
模式 A（官方 API）
  BASE_URL     : https://api.minimax.io/v1
  lite/classic : MiniMax-M2.7
  epic         : MiniMax-M3

模式 B（本地部署）
  BASE_URL     : http://localhost:30000/v1
  api_key      : 'EMPTY'
  lite/classic : MiniMaxAI/MiniMax-M2.7
  epic         : MiniMaxAI/MiniMax-M3
```

## 本地部署的一个真实注意点：推理输出

官方文档提到 M2.7 会**输出 reasoning 内容**（`--reasoning-parser minimax-append-think`）。

我在压力测试中实测到 M2.7 会吐 `<think>...</think>` 标签 —— **这对角色扮演是致命的**，
用户会看到角色"内心独白"打断沉浸感。

**上线前必须处理**：在 `llm.py` 的流式解析里剥掉 reasoning 段。当前代码**尚未处理**这一点，
接入真实 M2.7 后需要补：

```python

```

## 环境变量速查

| 变量 | 用途 | API 模式 | 本地部署 |
|---|---|---|---|
| `MINIMAX_API_KEY` | 凭证 | 必填 | 可省（自动用 `EMPTY`） |
| `MINIMAX_BASE_URL` | 端点 | 默认官方 | `http://localhost:30000/v1` |
| `MINIMAX_MODEL_PREFIX` | 模型名前缀 | `""` | `MiniMaxAI/` |
| `MINIMAX_EPIC_MODEL` | epic 档模型 | `MiniMax-M3` | 按实际部署填 |
| `PORT` | 服务端口 | `8080` | 同 |
