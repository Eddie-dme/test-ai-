# Google Play Console 表单填写草稿

上架时 Play Console 会要求逐项填写若干表格。答案全部**依据代码实际情况**
推导（核对于 2026-09-24），不是凭印象写的。填表时照抄即可。

---

## 一、数据安全（Data Safety）

这是审核最看重的一张表，填错会被拒。**依据**：`store.py` 的表结构 +
`server.py` 的对外调用。

### 收集哪些数据

| 类别 | 是否收集 | 说明 |
| --- | --- | --- |
| 邮箱地址 | ✅ 是 | 注册账号用（`users.email`） |
| 用户 ID | ✅ 是 | 账号标识（`users.id`） |
| 应用内消息 | ✅ 是 | 对话内容（`messages`） |
| 用户生成内容 | ✅ 是 | 自建角色、动态、相册图片 |
| 购买记录 | ✅ 是 | hearts 充值记录（`iap_purchases`） |
| 位置 | ❌ 否 | 代码里没有任何定位调用 |
| 设备标识符 | ❌ 否 | 无 IMEI / ANDROID_ID 读取 |
| 联系人 / 日历 | ❌ 否 | Manifest 未申请相关权限 |
| 照片 / 视频 | ❌ 否 | 除非用户主动上传 |
| 健康 / 财务信息 | ❌ 否 | 付费走 Google Play 结算，不接触卡号 |

### 关于这些数据

- **是否加密传输**：✅ 是（全站 HTTPS，Cloudflare + 源站）
- **用户能否请求删除**：✅ 是 —— 应用内「Delete account」自助删除，
  实测会级联清空全部关联数据（已用零残留验证）
- **数据处理是否可选**：邮箱与对话内容是核心功能所必需，非可选

### 数据共享

✅ **与第三方共享**，仅一家：

- **MiniMax**（`api.minimax.io`）—— 把对话文本发送过去生成角色回复。
  这是产品的核心机制，不共享就无法工作。

Play 表单中对应勾选「应用内消息」并说明共享目的为「App functionality」。
**不要再勾其他类别** —— 代码里没有别的对外调用。

### 其他声明

- 数据是否用于广告投放：❌ 否
- 数据是否用于个性化推荐：❌ 否（好感度与推荐无关）
- 是否有第三方分析 SDK：❌ 无

## 二、内容分级问卷

### 建议分级：**Teen / 13+**（港澳台区建议 12+）

依据实际内容作答：

- **暴力**：⚠️ 轻微 —— 角色扮演情境中的虚构冲突描写（剑、战斗意象），
  无写实血腥、无肢解、无针对真实人群的暴力
- **性内容**：⚠️ 暗示 —— 浪漫向剧情与情感描写，**无露骨性描写**。
  产品定位是 romantasy，保持在"言情小说"尺度
- **语言**：⚠️ 轻微 —— 角色设定包含 snarky 属性，可能出现轻度粗口
- **受控物质**：❌ 无
- **赌博**：❌ 无（hearts 是单向消耗的虚拟货币，不可兑换、无随机抽取玩法）
- **恐怖**：⚠️ 轻微 —— 部分角色设定涉及吸血鬼、幽灵等哥特意象
- **用户互动**：✅ **有** —— 这是关键项。应用含 UGC（自建角色、
  动态、评论）与用户间互动，必须如实勾选
- **位置共享**：❌ 无
- **数字商品购买**：✅ **有** —— hearts 充值

> ⚠️ 因含 UGC 与用户互动，必须同时确认应用内已提供
> **举报机制**（已有：`data-a="report"`）与**屏蔽能力**（已有），
> 否则会被按「UGC 政策」拒审。

## 三、其他表单

**广告**

- 是否含广告：**填表时要按当时的实际情况**
- 当前代码状态：**服务端有 AdMob 配置位**（`server.py` 的 `ADMOB_PUBLISHER`
  / `ADMOB_REWARDED` 环境变量），但**客户端尚未接入任何广告 SDK**
  （AndroidManifest 只有 INTERNET 与 ACCESS_NETWORK_STATE，无 AdMob 依赖）
- 若上架时仍未接入 → 填「不含广告」
- 若已接入 → 填「含广告」，并声明广告类型为「激励视频」

**目标受众**

- 年龄段：**13 岁及以上**（产品含浪漫主题）
- 是否面向儿童：❌ 否
- 后果：需避免被纳入「Designed for Families」计划

**政府应用 / 新闻应用 / 金融功能**：均 ❌ 否

**应用类别建议**：`Entertainment` 或 `Lifestyle`（角色扮演社交）
**标签建议**：AI、角色扮演、故事、社交

## 四、审核专用账号（重要）

**应用强制登录才能使用**，审核员拿到 APK 后没有账号就只能看到登录页，
无法评估任何功能 —— 这会被直接拒审。

Play Console 和 App Store Connect 都有「提供演示账号」的字段，填这里：

```
Email:    reviewer@lurvy.top
Password: VesperineReview2026
```

该账号已在生产环境创建并验证（能登录、能取到 6 个角色）。

**提交前的检查清单：**

- [ ] Play Console → 应用内容 → **应用访问权限** → 填写上述账号
- [ ] App Store Connect → 审核信息 → **登录信息** → 填写上述账号
- [ ] 确认该账号在生产环境可用（不要只在测试库创建）
- [ ] 审核通过后，可考虑修改该账号密码或停用

> 更新密码后记得同步更新两个后台的填写内容，否则后续版本更新审核会失败。
